# 表演与语音标记

默认提供“人类可读版”，仅在用户指定支持 SSML 的 TTS 服务后再转换机器标记。标记应服务于意思和笑点，不能淹没文本。

SSML 映射遵循 W3C Speech Synthesis Markup Language 1.1 中 `break`、`emphasis` 和 `prosody` 的语义。可选本地中文 TTS 优先评估 Apache-2.0 许可的 CosyVoice；使用前仍需分别检查所选模型权重与声音素材的许可。

## 人类可读标记

| 标记 | 意义 | 使用原则 |
|---|---|---|
| `/` | 短停顿或换气，约 0.2–0.4 秒 | 分开两个意群 |
| `//` | 节拍停顿，约 0.5–0.8 秒 | 放在揭示或笑点前 |
| `///` | 等笑或保持画面，约 1–2 秒 | 根据现场反应调整，不要抢下一句 |
| `[重]…[/重]` | 重读 | 标出改变解释的关键词 |
| `[轻]…[/轻]` | 降低音量 | 用于秘密、羞耻或反差 |
| `[慢]…[/慢]` | 放慢 | 让具体画面或荒谬逻辑被听清 |
| `[快]…[/快]` | 加快 | 表现慌乱、辩解或失控 |
| `[动作：…]` | 身体动作 | 只写观众能看见且能增加意义的动作 |
| `[看：左/右/观众]` | 视线落点 | 固定不同角色或制造共谋感 |
| `[状态：…]` | 短暂表演状态 | 用可执行的状态词，如镇定、犹豫、心虚；避免抽象心理分析 |
| `[角色：身份｜语速±%｜音高±st]` | 角色切换 | 一次声明，角色结束后写 `[回本人]` |

示意结构（不是固定台词）：

```text
我本来以为这是一个正常流程。//
[角色：工作人员｜语速-8%｜音高-1st]“我们这里非常人性化。”[/角色]
/ 然后他递给我 [重]第七张[/重] 表。///
[回本人][动作：双手接住不存在的一摞纸]
```

## 标记笑点节拍

- setup 内只在信息边界换气，不要制造虚假悬念。
- 在揭示前使用 `//`，让听众有时间形成预期。
- punchline 后优先使用 `///`，不要立刻解释或补词。
- tag 应等上一轮反应下降后再开始；若没有笑声，按正常节奏继续。
- 角色切换要同时改变至少两项：视线、身体、语速、音高或词汇。
- 动作本身已经表达的信息不要再用台词说明一遍。

## TTS 转换

确认供应商支持的 SSML 子集后再转换。通用映射可从以下形式开始：

```xml
<break time="300ms"/>       <!-- / -->
<break time="650ms"/>       <!-- // -->
<break time="1400ms"/>      <!-- /// -->
<emphasis level="strong">关键词</emphasis>
<prosody rate="92%" pitch="-1st">角色台词</prosody>
```

注意：

- 不同供应商对 `<emphasis>`、`pitch="st"` 和嵌套标签的支持不同。
- 笑声长度无法在录音前准确决定；生成音频时可先用 1.2–1.5 秒，再根据成品调整。
- 对中文，标点、分句和文本规范化通常比堆叠 prosody 标签更影响自然度。
- 输出 SSML 时同时保留一份无标签的纯文本逐字稿。

## 时长与排练

- 初始估算可按每分钟约 180–230 个汉字计算；现场停顿、笑声和 act-out 会显著拉长时间。
- 使用 `scripts/estimate_duration.py` 得到初始范围，然后至少朗读两遍记录真实时间。
- 如果超时，先删重复解释和较弱 tag，不要剪掉理解主笑点所需的事实。
- 记录每个笑点的开始时间、第一声反应、反应持续时间和下一句是否被盖住。
